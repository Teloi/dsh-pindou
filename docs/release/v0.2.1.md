## 发布 / Release

npm 包页面渲染的是包里的 README。仓库里的 README 继续用相对路径；`pnpm pack:npm`（`scripts/pack-npm.mjs`）只改写包里那份 README.md / README.en.md：图片钉到 `raw.githubusercontent.com/Teloi/dsh-pindou/v0.2.1/…`，相对链接钉到 `github.com/Teloi/dsh-pindou/blob|tree/v0.2.1/…`，每个目标都必须在该提交里存在，包里只要还剩一个相对的图片、srcset 或链接，脚本就以非零退出码失败。所以 **tag 必须在 npm publish 之前推上去，并且正好指向审计过的提交**，否则 npm 页面上的图会 404。
The npm package page renders the packed README. The repository keeps relative paths; `pnpm pack:npm` (`scripts/pack-npm.mjs`) rewrites only the packed README.md / README.en.md: images are pinned to `raw.githubusercontent.com/Teloi/dsh-pindou/v0.2.1/…`, relative links to `github.com/Teloi/dsh-pindou/blob|tree/v0.2.1/…`, every target must exist in that commit, and if any relative image, srcset or link is left in the package the script exits non-zero. So **the tag has to be pushed before npm publish, on exactly the audited commit**, or the images on the npm page 404.

防误发：`package.json` 的 `prepublishOnly` 会直接让 `npm publish` / `pnpm publish`（从目录发布）失败并提示「请用 pnpm pack:npm 产出的 tgz 发布」。只能发布审计过的 tgz：`npm publish <tgz> --ignore-scripts --access public`。
Guard: `prepublishOnly` in `package.json` makes `npm publish` / `pnpm publish` from the directory fail with "publish the tgz produced by pack:npm". Only the audited tgz is published: `npm publish <tgz> --ignore-scripts --access public`.
